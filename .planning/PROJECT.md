# DebugMate：面向 AI 专业学习场景的多模态报错诊断与复盘智能体

## What This Is

DebugMate 是一个面向人工智能专业大学生的多模态报错诊断智能体。用户可以提交终端报错文本、报错截图、相关代码和环境信息；系统通过视觉理解、错误分类、专属知识库检索和大模型推理，生成可追溯的文字诊断报告、动态诊断流程图以及语音复盘，并在一个统一结果页中呈现。

本项目首先服务于《校外实训》课程作业，同时按可复现的工程项目建设：本地仓库保存知识库源文件、提示词版本、评测集、运行证据、工作流说明和最终交付材料，云端智能体平台只承担模型编排与可交互演示。

## Core Value

对一个真实或可复现的 AI/Python 工程报错，DebugMate 必须基于专属知识库给出有依据、可执行、能说明不确定性的诊断，并同步生成文字、图像和语音三种关联输出。

### Active

- [ ] 用户可输入报错文本、终端截图、代码片段和基础环境信息，至少支持文本与图像两类输入。
- [ ] 系统能从截图中提取 Traceback、关键错误行、包名、版本号和设备信息，并保留原图用于结果对照。
- [ ] 系统能清理或遮蔽用户名、绝对路径、Token、邮箱等潜在敏感信息，再进入后续推理与展示。
- [ ] 系统能将问题路由到依赖/环境、路径/权限、Python 运行时、张量形状/类型、CUDA/显存、模型加载等诊断类别。
- [ ] 系统具有专属知识库，首版覆盖 Python、pip/venv、PyTorch、CUDA、Hugging Face、Ultralytics 和 Windows 路径问题，并为知识条目保存官方来源与更新时间。
- [ ] 诊断回答必须引用命中的知识片段，区分事实、推断和待补充信息；证据不足时不得编造确定性结论。
- [ ] 每次诊断生成统一的结构化诊断对象，至少包含错误类别、根因候选、证据、检查步骤、修复步骤、验证命令、置信度和局限。
- [ ] 同一结构化诊断对象必须派生三种关联输出：文字报告、动态流程图/诊断卡 PNG、语音复盘 MP3。
- [ ] 用户可在统一结果页查看原始输入、检索依据、文字报告、图像和音频，并获得可下载的结果文件。
- [ ] 项目保留至少四版提示词及同案例输出对比，能够解释每次修改解决了什么问题。
- [ ] 项目建立可重复执行的评测集，包含正确案例、信息不足案例、易混淆案例和安全/隐私案例，并输出结构化评分结果。
- [ ] 项目具备完整工程文档、运行证据、作品讲解 PPT、讲解稿、AI 配音、字幕和最终讲解视频。
- [ ] 所有课程交付物能够追溯到仓库中的源文件或生成脚本，避免只交不可复现的最终文件。

### Out of Scope

- 自动修改用户本机环境或执行未经确认的修复命令 — 首版只做诊断、建议和验证命令，避免破坏环境。
- 覆盖所有编程语言和所有 AI 框架 — 首版聚焦 Python/深度学习高频场景，保证知识库质量。
- 训练自有基础模型或视觉模型 — 时间有限，使用现有多模态大模型、嵌入模型和 TTS 能力。
- 收集或标注传统机器学习数据集 — 本项目选择课程第二类多模态智能体路线，不走第一类训练项目。
- 宣称替代专业工程师或保证修复成功 — 输出必须明确适用条件、置信度和剩余风险。
- 首版实现多人账号、复杂权限、支付、社区或移动原生应用 — 与课程核心价值无关。
- 将上传的真实 Token、密码或个人路径写入知识库、日志、PPT或演示视频 — 只保留脱敏证据。

## Context

- 课程允许选择大模型综合创意应用；智能体类作品必须包含专属知识库与完整工作流，并至少生成、融合两种以上模态。
- 项目最终必须有作品讲解 PPT 和视频，展示工具分工、提示词优化、完整作品、局限和改进方案。
- 用户时间有限，希望尽可能由 LLM 和自动化脚本完成，避免人工搜集和标注数据集。
- 当前工作区为全新空目录；本机可用 Python 3.13、FFmpeg 8.1、Git 和 NVIDIA RTX 4050 Laptop GPU 6GB，但没有 Docker。
- 已确认的多模态合规口径是：不能只把截图输入算作多模态；作品本身必须从同一诊断结果动态生成文字、图像和语音。
- 云端编排平台优先考虑扣子 Coze；如果知识库、导出、TTS或工作流证据能力受限，则退回 Dify Cloud 或可控的 Python Web 实现。
- 知识库优先使用官方技术文档和可核验页面，不以未经验证的 LLM 生成内容充当事实来源。

## Constraints

- **时间**: 首个可提交版本必须以短周期完成为目标 — 优先课程合规和演示闭环，避免研究型扩张。
- **人工投入**: 用户不承担数据集采集、标注或大批量内容整理 — 资料采集、测试生成、PPT和视频应尽量自动化。
- **平台依赖**: 云端平台可能需要登录、验证码、额度或模型配置 — 必须保留平台无关的知识库、提示词和评测资产，并准备降级路径。
- **可复现性**: 关键提示词、知识来源、评测输入输出和生成脚本必须版本化 — 平台截图不能成为唯一证据。
- **多模态**: 文字、图像和语音必须由同一次诊断的结构化数据派生 — 静态装饰图或无关配音不计入核心成果。
- **真实性**: 课程截图和视频只能使用真实运行结果 — 禁止用生成图片伪造训练、评测或平台运行证据。
- **隐私**: 输入在日志、知识库和交付物中默认脱敏 — 测试案例优先使用自动生成并可复现的虚构路径和虚构身份。
- **成本**: 优先免费额度和本机可用工具 — 任何付费 API、订阅或云部署必须在实现前单独确认。
- **兼容性**: 首版以 Windows 桌面浏览器演示为主 — 不要求移动端原生适配。
