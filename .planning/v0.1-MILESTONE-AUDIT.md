# DebugMate V0.1 Milestone Audit

## Verdict

DebugMate 的固定本地演示链已经完整，但当前仓库证据不足以支持“38/38 requirements complete”或“课程提交包已完成”。必须先补齐真实输入、截图入口和 Dify 端到端接线，再最后刷新课程媒体。

## Confirmed Complete Flows

1. 固定演示输入 → 本地脱敏 → HMAC 审批 → local-rule diagnosis → 严格 DiagnosisRecord。
2. DiagnosisRecord → Markdown、确定性 PNG、recap/MP3 → consistency gate → Gradio → verifier-backed ZIP。
3. allowlisted replay → 来源验证 → completed/partial/failed 状态与最小重试。
4. Dify C01-C07 的独立能力证据均 tracked、not ignored、SHA-256 匹配并通过对应 validator。

## Critical Integration Gaps

### 1. 普通 UI 不接受真实用户输入

当前“脱敏后的输入”是只读结果面板，预览按钮固定使用 `LOCAL_RULE_DEMO_ERROR`、`LOCAL_RULE_DEMO_CODE` 和 `LOCAL_RULE_DEMO_ENVIRONMENT`。用户无法在普通页面提交报错文本、代码、环境或截图。

### 2. Dify 能力没有组成同一次用户诊断链

C01-C07 分别有真实证据，但它们来自多次独立探针。普通 UI 明确显示 `local-rule-v1（本地规则，无云端调用）`，尚未验证：

`用户输入 → 本地脱敏审批 → 同一次 Dify workflow → 本地 Pydantic 校验 → Markdown/PNG/MP3 → Gradio/ZIP`

### 3. 课程媒体属于历史版本

PPTX、MP4、SRT、三张课程截图以及两个 manifest 均生成于 2026-07-19。它们仍包含 Dify smoke 待办、旧测试数量、旧 UI 和 SAPI 待听验等过期表述；`asset-manifest.json` 中四份课程源文档的哈希也已与当前文件不一致。
