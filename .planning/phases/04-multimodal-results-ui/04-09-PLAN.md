# Phase 04 local-rule live VQ-01 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` task-by-task. Use a fresh implementation agent and a fresh reviewer for each task; do not run tasks in parallel because later tasks depend on the completed local-live boundary.

**Goal:** Make the repaired workbench produce one genuine, repeatable, privacy-approved local live diagnosis for the fixed `ModuleNotFoundError` demonstration, with truthful local provenance and real Edge VQ-01 evidence.

**Architecture:** Keep the existing Phase 2/3/4 trust boundaries intact. A committed official-source snapshot supplies one narrow local rule; a strict loader turns it into a retrieval provider and a deterministic generation provider for `DiagnosisWorkflow`. The loopback UI creates a new `InputEnvelope`, renders a redaction preview, requires a separate approval click, then hands the resulting `ApprovedRedactedInput` to `ResultApplicationService`; normal evidence, report, PNG, and SAPI-only audio composition continue through the existing verified result path.

**Tech Stack:** CPython 3.13, Pydantic v2 strict models, existing `DiagnosisWorkflow`, `ProductionExtractionProvider`, privacy approval gateway, `ResultApplicationService`, Pillow, Windows SAPI, Gradio 6, pytest, Playwright Edge, PowerShell.

## Global Constraints

- Execute only after `04-08` has completed and its unique-grid browser gate is green.
- The live path is exactly `InputEnvelope -> redact_input -> approve_preview -> DiagnosisWorkflow`; no prebuilt outcome, raw path, shell action, user-provided file, or user-provided fixture ID may enter it.
- `knowledge/snapshots/local-rule/` is the sole source for the local rule. The live implementation must not read `fixtures/**` or `tests/**`, even as a fallback.
- The live rule and live composition path make no network call. In particular, they must not instantiate or call Dify, Edge TTS, HTTP clients, sockets, or an LLM provider. Live audio may use the existing local SAPI adapter only; replay-only adapters are constructed lazily after a replay mode decision.
- The exact diagnostic evidence backend must be `local-rule-v1`; UI and evidence must say it is local and must never imply Dify, LLM, cloud, or replay success.
- Each approved click must use a new `case_id`; completed live calls must produce a new source `run_id` and verified `result_id`, `mode=live`, `fixture_id=null`, and `fixture_name=null`.
- Preserve capability URLs, output scanning, manifest verification, component-native rendering, 04-07 external-TTS statuses, and the immutable archived GAP-01 screenshot.
- Do not mark VQ-02..VQ-15 complete. This plan records only a real completed+live VQ-01 proof.

<threat_model>

| Threat | Control and testable invariant |
|---|---|
| A replay or precomputed outcome is presented as live | Live callback never calls `load_replay*`, has no fixture input, invokes `ResultApplicationService.diagnose_and_compose_events`, and asserts `mode=live`, both fixture fields `None`, and fresh identities. |
| Snapshot tampering/path escape silently changes advice | Manifest accepts a fixed key set, fixed version and controlled payload filename; resolve within `knowledge/snapshots/local-rule`; reject symlinks, `..`, extra files, invalid JSON/schema, and SHA-256 mismatch before creating either provider. |
| A local demo covertly uses cloud/network services | `LocalRuleRetrievalProvider` and `LocalRuleGenerationProvider` have no transport dependency; the live composer selects only `SapiTtsAdapter`; tests poison Dify, Edge, HTTP, and socket entry points and still complete the local run. |
| Raw or unapproved text reaches workflow | UI stores `PreviewBundle` only after `redact_input`; second callback calls `approve_preview` with process-local key and passes its strict result directly. Invalid/missing/tampered preview stays disabled/failed and calls no workflow. |
| Backend wording overclaims model capabilities | Source evidence `run.json` backend is exactly `local-rule-v1`; UI includes the literal local provenance label only in the live flow. No Dify/LLM/cloud success copy appears in live event frames, screenshot, report, card, recap, or result bundle. |
| A local path or secret reaches UI/evidence | Reuse existing output scanner/verifier and only expose native capability URLs. Regression test uses `SECRET_SENTINEL_DO_NOT_LOG` in a non-displayed negative case and asserts it is absent from callback representations, evidence, screenshot JSON, and result members. |
</threat_model>
