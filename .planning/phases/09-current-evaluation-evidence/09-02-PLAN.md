<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Run/result bundles → Phase 09 collector | A path or checksum claim is untrusted until repository-root, manifest, artifact, citation, and privacy validation succeeds. |
| Validated contracts → reports | Projection code must not introduce unsafe text, stale claims, inferred provenance, or nondeterminism. |
| Phase 09 workspace → frozen Phase 10 media | Evidence work must not alter or regenerate final course assets. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Severity | Mitigation Plan |
|---|---|---|---|---|---|
| T-09-04 | Information disclosure | collector/projections | mitigate | high | Allowlisted safe projections plus existing recursive export, binary, ZIP, and secret scans; rejected values are never echoed. |
| T-09-06 | Tampering | result/citation/media inputs | mitigate | high | Reopen with existing result/evidence validators; require hash, MIME, ZIP, FFprobe, identity, and citation checks. |
| T-09-07 | Tampering | course media paths | mitigate | high | Baseline inventory and fail-on-diff/new-file PowerShell gate; deny course builders in Phase 09. |
| T-09-05 | Spoofing | eligibility labels | mitigate | high | State-aware source collection prevents absent artifacts from becoming media-eligible claims. |
| T-09-SIZE | Denial of service | source/read operations | mitigate | medium | Reuse bounded contract fields and validators; reject out-of-root, symlink, oversized, and recursive content. |

All high-severity entries block report staging and evidence promotion; they cannot be waived by a Markdown-only result.
