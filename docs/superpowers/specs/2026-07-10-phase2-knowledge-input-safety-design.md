# DebugMate Phase 2 设计：精选官方知识源自动化与输入安全

**日期：** 2026-07-10  
**状态：** 架构方向已确认，等待书面规格复核  
**对应需求：** INP-01、SAFE-01～SAFE-03、KNOW-01～KNOW-05

## 1. 目标与边界

Phase 2 建立两条可独立测试、共享审计合同的流水线：

1. 从精选官方页面自动生成可重建、可追溯的结构化知识摘录。
2. 在文本、代码、环境和终端截图离开本机前完成自动脱敏，并要求用户确认预览。

本阶段不实现最终诊断推理、完整 OCR 字段纠错界面、PNG/MP3 产物或 Gradio 结果页。云端调用仍只能经过 Phase 1 的安全适配层。

## 2. 已选方案

- 知识源采用“精选官方源自动化”，每个产品家族选择 2～4 个高价值官方页面。
- 仓库保存结构化诊断摘录，不保存完整网页快照。
- 输入采用“自动脱敏＋上传前预览确认”。
- 原始输入只存在于本机临时目录；Git、日志、evidence 和课程材料只接收脱敏结果。

## 3. 系统架构

```text
knowledge/sources.json
  → 域名白名单与来源合同校验
  → HTTP 抓取与原文 SHA-256
  → HTML 主体/标题/代码块提取
  → 诊断主题切分与去重
  → 确定性模板生成短诊断事实
  → 来源锚点与摘录哈希校验
  → knowledge/notes/*.md
  → build-manifest.json / Dify upload bundle

InputEnvelope
  → 至少 text 或 screenshot 存在
  → 文本规则扫描 + OCR 候选框
  → RedactionPlan
  → 脱敏文本/代码/环境/截图
  → PreviewBundle + RedactionAudit
  → 用户确认
  → ApprovedRedactedInput
  → CloudGateway
```

知识与输入两条流水线只通过版本化模型和文件合同交互，不互相导入实现细节。

## 4. 精选官方知识源

### 4.1 首版覆盖

来源只允许官方域名，覆盖七个家族：

- Python：异常、导入、`venv`、Windows 路径行为。
- pip/Packaging：安装定位、依赖解析、环境诊断。
- PyTorch：张量形状/类型、模型加载、CUDA 运行时与显存。
- NVIDIA CUDA：驱动、Toolkit、兼容性和常见运行错误。
- Hugging Face：Transformers 模型加载、缓存和设备配置。
- Ultralytics：安装、模型加载、训练/推理环境问题。
- Microsoft Windows：路径、权限、环境变量和 PowerShell。

每个家族首版只保留 2～4 个与六类课程报错直接相关的页面，禁止无限爬取。

### 4.2 来源合同

`knowledge/sources.json` 的每个条目必须包含：

- 稳定 `source_id`、标题、URL、产品、版本范围和适用平台。
- 允许的官方域名、抓取时间、HTTP 状态、内容 SHA-256。
- 许可或使用条款说明、选取理由、目标错误类别。
- 页面标题定位或 CSS 主体选择器；选择器失效时来源进入隔离区。

来源清单通过现有 `knowledge/manifest.schema.json` 的扩展合同验证。下载失败、域名跳转出白名单、正文为空或内容哈希异常时，不生成可用知识文档。

### 4.3 结构化摘录

每份 `knowledge/notes/<source_id>.md` 使用统一结构：

- 适用症状与错误类别。
- 可观察事实和诊断检查。
- 版本/平台限制。
- 官方章节标题与 URL 锚点。
- 确定性诊断说明和必要的短摘录。
- 原文哈希、摘录生成器版本和质量状态。

首版权威知识笔记只使用确定性模板和已提取短事实。锚点存在或词汇重合不能证明大模型释义被来源蕴含，因此在具备独立蕴含验证器之前，任何可选 LLM 文本都不得进入 Markdown、构建 manifest 或 Dify 同步内容。

### 4.4 构建与 Dify 同步

构建命令生成不可变 `knowledge/build/<build_id>/`，包含文档、来源 manifest、文档哈希、分块配置和同步清单。Dify 同步器只读取该目录，并提供 dry-run；删除或覆盖远端文档必须显式确认。同步后验证文档数量、source ID、内容哈希和检索配置，不能仅依赖平台截图。

## 5. 输入与脱敏合同

### 5.1 输入模型

`InputEnvelope` 包含 `case_id`、错误文本、截图路径、代码片段和环境信息。错误文本与截图至少提供一项，否则在本机拒绝创建上传任务。

原始截图仅允许 PNG/JPEG，限制文件大小和像素数，并通过文件头识别真实格式。代码和文本设置长度上限，拒绝二进制内容与目录上传。

### 5.2 敏感候选

`SecretCandidate` 记录类型、来源字段、字符区间或 OCR 边界框、匹配规则、置信度和建议动作。首版检测：

- API Token、Bearer 值、密码/密钥赋值、私钥头。
- 邮箱、用户名、学号式标识和常见内部 ID。
- Windows/Unix 绝对路径与用户目录。
- 内网 IP、主机名以及 URL 查询参数中的凭据。

文本使用确定性正则、路径解析和高熵字符串规则。截图使用 RapidOCR CPU 获取文字与坐标，再复用同一文本规则；Pillow 根据坐标绘制不可逆遮挡，不使用生成式图像编辑。

### 5.3 预览与确认

脱敏后生成 `PreviewBundle`：

- 脱敏文本、代码和环境信息。
- 原截图缩略图与脱敏截图。
- 按类型汇总的候选数量和审计明细。
- 原始输入哈希、脱敏结果哈希、规则版本和 OCR 后端版本。

用户确认后生成不可伪造的 `ApprovedRedactedInput`，绑定 `case_id`、预览哈希、确认时间和随机 `approval_id`。`CloudGateway` 的公开接口只接受该类型；普通 `InputEnvelope` 或未确认预览无法调用 Dify。

用户可在确认前取消某个误报遮挡，但每次修改都会重新生成预览哈希并废止旧确认。Token、私钥和明确密码不允许恢复为明文上传。

## 6. 输出二次扫描与提示注入

所有知识正文、用户日志、代码和截图 OCR 文本均标记为不可信数据。它们只能进入数据字段，不能改变系统指令、选择工具或触发命令。

安全策略包括：

- 将不可信文本放入明确的数据边界，不把它拼接为控制指令。
- 识别“忽略此前指令”“输出密钥”“调用工具”等注入模式，并在审计中标记。
- Phase 2 不提供任何命令执行器；`CommandStep` 仍只是数据。
- 在 evidence、日志和导出对象写入前运行第二次敏感扫描。
- 后续 PNG 元数据和音频讲稿复用同一 `OutputSafetyScanner`，当前阶段先冻结接口和文本/JSON实现。

二次扫描失败时产物进入隔离区，不得进入课程材料，也不得被标记为成功 evidence。

## 7. 错误处理

- 来源抓取超时：有限重试并记录失败，不使用搜索摘要替代官方正文。
- 页面结构变化：选择器或标题锚点失效即隔离，禁止静默生成空摘录。
- LLM 摘录不合规：最多一次结构修复；仍失败则使用确定性降级或阻止发布。
- OCR 初始化/识别失败：保留文本输入路径，截图不得上传云端，提示用户补充错误文本。
- 脱敏候选过多或置信度不足：要求人工预览，不自动发送。
- 用户取消确认：删除临时原始文件和旧 approval，不产生云端请求。
- 二次扫描发现敏感内容：阻止 evidence 发布并生成安全错误码，不记录原始敏感值。

## 8. 测试策略

### 8.1 知识库

- 使用本地 HTML fixture 测试标题、正文、代码块、锚点与哈希提取。
- 测试域名跳转、404、空正文、重复来源、内容漂移和选择器失效。
- 对固定来源生成 golden note，确保重复构建字节一致。
- 验证每份 note 的声明都具有 source ID 与章节定位。
- dry-run 同步测试文档数量、元数据、哈希和删除保护。

### 8.2 输入安全

- 覆盖 Token、密码、邮箱、用户名、Windows/Unix 路径、内网 IP 与高熵串。
- 使用自动生成的虚构截图测试 OCR 坐标与像素遮挡，不使用真实个人截图。
- 验证原始内容不进入 repr、异常、日志、manifest 或 tracked files。
- 验证未确认、确认后被修改、旧 approval 和 case ID 不一致均无法调用云端。
- 覆盖中英文路径、CRLF、代码块、Traceback 和提示注入样例。

### 8.3 阶段验收

- 七个产品家族均有合法官方来源和至少一份结构化 note。
- 知识构建可重复，manifest/文档哈希一致。
- 文本与截图至少一项的输入约束不可绕过。
- 自动脱敏、预览确认、审批失效和二次扫描均有回归测试。
- 默认离线测试不访问网络；在线抓取和 Dify 同步使用独立 marker。

## 9. 实施分解

Phase 2 实施计划分为三部分并串行验收：

1. 输入合同、文本脱敏、预览审批与云端类型门禁。
2. 截图 OCR 脱敏、二次扫描与隐私 evidence。
3. 精选官方源抓取、结构化摘录、覆盖报告与 Dify 同步包。

该顺序优先封住隐私边界，再允许任何新增联网或云端数据流。
