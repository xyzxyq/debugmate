# DebugMate Dark Command Center 设计规范

## 目标

把现有 Gradio 三列调试页改造成克制、专业的深色开发者诊断工作台，让用户在 1366×768 桌面视口中优先看到诊断状态、关键结论和下一步操作，同时保留现有脱敏、回放、纠错、三模态结果、失败降级和 ZIP 下载能力。

## 设计方向

- 气质：深色开发者控制台，但不使用霓虹、紫色渐变、玻璃拟态或营销式 Hero。
- 配色：石墨黑主背景、深灰分层表面、冷青色主操作、琥珀色警告、红色失败、暖白正文。
- 字体：中文使用系统无衬线字体；运行 ID、错误原文和命令使用 `Cascadia Mono` / `Consolas`。
- 密度：紧凑、可扫描；通过间距、分组和分隔线建立层级，减少卡片嵌套和大面积空白。

## 页面结构

1. **顶部命令栏**：产品名、当前状态、运行模式、案例名和来源运行 ID；保持 sticky 和 `aria-live` 状态播报。
2. **左侧操作轨**：宽度约 280px，包含“新诊断”和“固定回放”两个区域；抽取字段与纠错放入折叠区，避免首屏形成超长表单。
3. **中央诊断主画布**：显示异常类别、置信度、部分完成/失败信息和下一步操作；关键回溯作为事实表中的高优先级行保持首屏可见，事实与证据使用紧凑表格并限制局部滚动。
4. **右侧结果工作区**：报告、诊断卡、语音复盘、引用下载使用统一标签栏；默认保持文字报告，部分完成态在失败详情中明确指出失败产物与重试范围，不新增标签选择状态。
5. **底部安全提示**：收束为单行次要说明，不重复占用主内容空间。

## 组件视觉

- 页面背景 `#0b0f14`，一级表面 `#111820`，二级表面 `#17212b`。
- 主文字 `#e8edf2`，次文字 `#91a0ad`，边框 `#293642`。
- 主色 `#27b3c2`，hover `#35c6d5`；警告 `#e7a84b`；失败 `#ef6b73`；成功 `#4ecb8d`。
- 圆角 8px，阴影仅用于 sticky 命令栏和浮层，不给每个区域加阴影。
- 按钮高度 38–42px；主按钮实心青色，次按钮深色描边，危险/重试按钮按状态着色。
- 表格取消粗黑网格，改为细分隔线、表头弱底色、单元格 12–14px；技术 ID 允许换行。

## 交互约束

- 不改变任何回调函数签名、输出数组顺序、`elem_id`、结果合同或服务行为。
- 键盘 Tab 顺序、焦点轮廓、原生 Tabs/Accordion/Audio/Download 控件保持可达。
- 1366×768 使用三区域布局；900–1199px 收为左侧轨 + 结果主区，证据区换行；低于 900px 单列。
- 长报告、命令、事实和引用只在自身容器滚动，页面不得出现整体横向滚动。
- 完成、部分完成、失败必须同时使用图标、文字和颜色表达，不能只依赖颜色。

## 范围边界

- 不新增后端 API、数据库、账号、主题切换或移动端专属交互。
- 不引入 React、Tailwind 或新的前端构建链；继续使用 Gradio 6 + HTML/CSS。
- 不隐藏课程要求所需的知识引用、提示词证据、回放标识或失败细节。
- 现有真实截图会在改版后重新生成，旧截图保留为历史证据但不作为新版交付图。

## 验收标准

- 首屏视觉焦点明确落在状态、诊断摘要和结果标签，而不是长输入表单。
- 深色主题在完成、部分完成、失败和长内容四种状态下可读且无裁切。
- 现有 UI/view/callback 测试全部通过；新增 CSS/结构合同测试覆盖颜色 token、布局类和折叠区。
- 真实 Microsoft Edge 通过键盘、200% 缩放、长内容、同次 ZIP 下载和状态辨识测试。
- 生成至少三张新版真实 Edge 截图：完成态、TTS 部分完成、PNG 部分完成。
