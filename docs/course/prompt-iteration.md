# 提示词 V1–V4 优化说明

| 版本 | 主要问题 | 新增约束 | 课程展示结论 |
|---|---|---|---|
| V1 基线 | 格式不固定、依据不清 | 基础诊断字段、禁止自动执行 | 能回答，但不够稳定可审计 |
| V2 引用 | 事实与推断混杂 | fact/evidence 绑定、缺失信息、注入边界 | 回答开始有证据链 |
| V3 可靠性 | JSON 漂移、命令信息不全 | Schema、置信度、影响/预期/回退 | 可被程序校验和派生产物 |
| V4 课程版 | 多模态长度与表述可能不一致 | recap 长度、中文解释、英文原文、回放真实性 | 适合报告、PNG、MP3 同源展示 |

固定 `ModuleNotFoundError` 案例的核心结论在四版中保持一致：先确认当前 Python 解释器，再检查包是否安装在该环境，审阅命令后才执行安装，并用导入命令验证。优化重点不是“把答案写得更长”，而是让依据、结构、安全边界和三模态一致性更明确。

V0.1 不伪造 V2–V4 的云端批量分数。当前 Phase 09 账本保持四版同一输入、事实、检索、知识库和 Schema 身份；V1 为已接受合同基线，V2–V4 明确标为 blocked/contract-only，未宣称独立 provider 生成。Dify envelope 的真实命中证据和 local fallback 的媒体证据分别记录，避免混淆 provenance。
