# DebugMate V0.1 代表性演示案例

## 使用原则

- 所有截图来自 2026-07-19 的真实 Microsoft Edge 自动化运行，不使用生成图片伪造界面结果。
- 案例中的用户名、路径、包名和身份均为虚构或已脱敏内容。
- “离线回放”会在页面上明确标注，不冒充 Dify 或云端实时调用。
- V0.1 用少量案例证明完整流程，不宣称达到生产部署或统计评测标准。

## 案例 1：ModuleNotFoundError 完整诊断

输入为虚构依赖包 `demo_missing_pkg` 缺失。系统展示脱敏输入、错误分类、事实与引用、中文报告、确定性诊断卡、语音复盘和完整 ZIP 下载。

- 状态：完成
- 后端：`local-rule-v1` 离线回放
- 展示重点：专属知识来源、三模态同源、来源运行标识、结果包下载
- 截图：`evidence/course-v0.1/screenshots/01-completed-overview.png`

## 案例 2：语音生成失败后的部分完成

同一诊断中模拟 `tts_failed`。系统没有把整体结果伪装成成功，而是保留文字报告、诊断卡和复盘稿，并明确给出“仅重试语音复盘”的范围。

- 状态：部分完成
- 展示重点：失败节点、安全错误码、可用结果、最小重试范围
- 截图：`evidence/course-v0.1/screenshots/02-tts-partial.png`

## 案例 3：诊断卡失败后的部分完成

同一诊断中模拟 `png_layout_failed`。文字报告和语音仍可使用，页面明确提示只重试诊断卡生成，证明三模态管线可以诚实降级。

- 状态：部分完成
- 展示重点：多模态阶段独立状态、语音后端与时长、可恢复操作
- 截图：`evidence/course-v0.1/screenshots/03-card-partial.png`

## 案例 4：长报告与长命令

使用 `long-content` 固定案例验证长报告具有局部滚动、长命令内容末尾仍可访问、诊断卡保持比例且页面不出现整体横向溢出。

- 状态：完成
- fixture：`fixtures/replay/long-content/`
- 自动验证：`tests/ui/test_browser.py::test_vq_04_long_content_commands_and_vq_05_tall_card_in_real_edge`
- 展示建议：录制视频时现场切换到该案例并展开“命令说明”区域，不额外维护一张冗余全页截图。

## V0.1 已知限制

- 当前稳定演示路径以本地规则与固定回放为主，Dify/视觉大模型在线调用仍受账号、额度和 provider 配置影响。
- 代表性案例用于课程展示，不构成对全部 Python/AI 报错的覆盖率证明。
- 本地 SAPI 音频已通过文件、解码和非静音机器检查，正式录屏前仍应人工试听一次。
- 系统只提供诊断、建议和验证命令，不会自动执行安装或修复命令。
